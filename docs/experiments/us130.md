## Recorte

- Entrada escolhida: duas árvores **brutas** SonarQube do mesmo projeto, completas,
  com componentes `FIL` identificados por `path`. `.metrics` e parâmetros de cálculo
  são formatos diferentes e não são aceitos diretamente.
- Métrica única: `complexity`, valor bruto de complexidade ciclomática do arquivo.
  A seleção decorre de sua presença nas fixtures, não de uma aprovação do PO.
- Correspondência: igualdade exata de caminho, sensível a maiúsculas e separadores.
  Mudança de caminho aparece como removido + adicionado; não detecta renomeação.
- Diferença: atual menos anterior, somente com dois valores disponíveis.
  Zero é dado válido; ausência permanece `None`/`null`.
- Não se reutiliza `diff`, pois ele trunca diferenças negativas e possui outra semântica.
  A implementação deve seguir as funções puras do Core e reutilizar sua validação de métricas.

## Limites

Adicionado/removido significa presença nas duas entradas fornecidas, não uma operação
Git comprovada. Coleta parcial, filtros ou mudança de escopo podem produzir a mesma
aparência. Paginação declaradamente incompleta deve ser rejeitada; sem metadados não
é possível provar completude. Chave de projeto Sonar não comprova identidade Git.

Não há seleção automática de análise/release, acesso ao banco, endpoint, coleta,
alteração de fórmulas, classificação de melhora/piora, causalidade ou atribuição de
pontos à medida/TSQMI. O experimento inclui arquivos vazios para preservar o retrato
bruto; o cálculo atual exclui `ncloc=0` em consumidores e tem outro universo de entrada.

## Executar

Na raiz do Core, com Python 3.10 ou superior:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PYTHONPATH=src .venv/bin/python examples/compare_file_complexity.py \
  tests/unit/data/us130/before.json tests/unit/data/us130/after.json
```

O comando escreve JSON em stdout, incluindo nomes dos dois arquivos de entrada e
`metric: complexity`. As duas entradas de demonstração são **sintéticas**.
Não é um comando novo da CLI do produto. Para entradas próprias, substitua os dois
caminhos por árvores brutas completas do mesmo projeto e branch Sonar, com
`baseComponent.key`, `components[].qualifier`, `path` e `measures`.

Recorte do resultado (valores brutos, sem julgamento de qualidade):

| Caminho | Anterior | Atual | Diferença | `file_status` | `missing_metric` |
| --- | --- | --- | --- | --- | --- |
| `src/changed.py` | 6 | 4 | -2 | `matched` | `[]` |
| `src/unchanged.py` | 2 | 2 | 0 | `matched` | `[]` |
| `src/zero.py` | 0 | 1 | 1 | `matched` | `[]` |
| `src/added.py` | null | 0 | null | `added` | `[]` |
| `src/removed.py` | 3 | null | null | `removed` | `[]` |
| `src/missing_before.py` | null | 7 | null | `matched` | `["previous"]` |
| `src/missing_after.py` | 5 | null | null | `matched` | `["current"]` |
| `src/missing_both.py` | null | null | null | `matched` | `["previous", "current"]` |

`missing_metric` enumera os lados em que o arquivo **existe**, mas o valor foi
omitido ou é `null`. Arquivo ausente é descrito pelo status de presença, não pela
lista de métrica ausente. As linhas saem ordenadas pelo caminho. Não há arredondamento.

`core.file_comparison.compare_file_complexity(previous, current)` também aceita
os objetos já carregados e retorna a lista de linhas, sem modificar as entradas.
É módulo experimental, sem mudança nos exports públicos do Core.

Valores negativos, não numéricos, booleanos ou não finitos são erros, não ausência.
Caminhos e métricas duplicados são rejeitados. Se `paging` existir, deve declarar
uma única página completa e consistente (`pageIndex=1`, `total=len(components)`,
`pageSize` suficiente). Não há busca de páginas. Sem `paging`, o chamador assume
a responsabilidade por confirmar completude. A branch, quando informada, deve
coincidir nos dois lados, inclusive quanto à presença desse metadado.

## Testar

```bash
.venv/bin/python -m pip install pytest pytest-cov pytest-mock requests black flake8 build
PYTHONPATH=src .venv/bin/python -m pytest tests --cov=src
.venv/bin/python -m black --check src tests examples
.venv/bin/python -m flake8 src tests examples parser.py
.venv/bin/python -m compileall -q src tests examples
.venv/bin/python -m build
```

Os testes cobrem valores crescentes, decrescentes e iguais, zero, ausência nos dois
lados, inclusão/remoção, qualificadores, identidade, paginação, duplicatas, dados
inválidos, não mutação das entradas e execução do exemplo. A árvore histórica é
comparada consigo mesma, validando sete arquivos e os valores já versionados;
isso não demonstra evolução entre releases reais.

Para explicar o experimento: comece pela origem das fixtures, mostre a linha 6 → 4,
compare zero com `null`, explique inclusão/remoção por presença e termine pelo
limite entre métrica bruta, medida normalizada e TSQMI. A semântica da métrica e
o contexto precisam ser verificados antes de falar em melhora ou piora.
